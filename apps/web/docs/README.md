# @pux/web

Jobs 的网页（Vite + React 19 + TypeScript + Tailwind v4 + TanStack Router/Query + PixiJS）。第一眼是城；结论在第二层。

- 开发：先 `pnpm world`、`pnpm api`，再 `pnpm web`（`http://127.0.0.1:5321/`，代理 `/api`、`/evidence`、`/reports` 与 WebSocket 到 API）。
- 构建：`pnpm web:build` → `apps/web/dist`，由 API 托管（`pnpm jobsworld` 首次启动会自动构建）。

## 页面

| 路径 | 页面 |
|---|---|
| `/` | 城：侧视像素城市 + 右侧「此刻」。默认「按产品」：每个上线中的产品一组（打开过 / 看到的人数，点名字进产品页），下面列出此刻正在用它的人（第几步、在哪、在想什么；排队的不算），点人在城里找到他并展开人物卡（此刻的屏幕、在想什么、「看这次使用」）；切到「所有人」是全城的人。点人看他在做什么、在用什么、在想什么，可追问 |
| `/products` | 已发布的产品：每行是它此刻的五层人数与评分；有人在用时名字旁是「N 人在用」和他们的头像 |
| `/products/:id` | 一个产品。最上面是「此刻在用」（`#now`）：每个正在用它的人一行，带此刻的屏幕缩略图、第几步、在哪、在想什么，卡在需要人介入时标「等人帮忙」，点一行直接进这次使用；没人在用时一行说明，排队的只给人数（「另有 N 人排队」）。下面是 `结论`（标题、现状、如果只改一件事、最让人难受 / 让人高兴 / 会留下的人 / 会走的人 / 看到了却没点开——每一句可展开看是谁、原话、当时的屏幕）、`人`（用过的人：此刻在用的排最前，排队的标「排队中」排最后；注意到了没点开的人）、`口碑`（商店页、评论、动态）、`工程附录`（亲历的问题含复现步骤；用户看不到的技术信号）。右栏：人数（标注「模拟」）、宣发强度、投给谁、把手机递给几个人。页头右侧（仅管理员）：暂停 / 继续、结束、`清零`（确认后城里关于它的经历全部归零，产品留着、此刻重新上线）、`下线`（确认时选「保留城里的经历」或「连同经历一起删除」，下线后回到产品列表） |
| `/people`、`/people/:id` | 居民列表；一个人的画像、此刻、今天的日程、家人与熟人、记忆、用过的产品、收件箱（邮件与短信，点开看全文，HTML 邮件在不执行脚本的沙箱里，可下载原始邮件；眼睛图标表示他在邮箱里点开过） |
| `/sessions/:id` | 一次使用的逐步回看：截图、想法、动作（含在产品和邮箱之间切换）、世界事件、这次收到的信、事后追问。进行中的使用在时间线上方多一块「正在进行 · 最新一步」（每 4 秒刷新，可跳到时间线里那一步） |
| `/human` | 需要人介入的任务（有待处理时导航里才出现） |
| `/settings[?tab=]` | 设置（仅管理员；顶栏右侧的齿轮图标，还没接入模型时带琥珀呼吸点）。所有「配置」性质的功能都在这里，按二级标签分类（≥1024px 时左边是竖排的分类（14rem，随页面滚动固定在原位），右边是这一类的配置（最宽 56rem）；更窄时分类收到上方横向排开，可横向滑动，当前那一项自动滑进视野；`tab` 省略时是「模型」）：`模型`（添加供应商、凭证（Vertex 另有「使用这台机器的 gcloud 登录」按钮：容器里还没挂 gcloud 配置目录时先请宿主机补上并等服务重启，做不到时提示运行一次 `jobsworld up`；没登录时提示 `gcloud auth login`）、勾选模型与用途、全局顺序（拖动 / 按钮 / 键盘）、保存前差异、测试、版本与回滚；还没接入模型的管理员第一次打开会被带到这里）、`public` 公网链接（保存后几秒内生效，标出来自环境变量还是只有本机能访问）、`mail` 居民邮箱（现在的域名与能不能收真实邮件、贴 Cloudflare API Token 一键开通 / 重新部署 / 关闭、令牌需要的权限、收信规则用了多少、测试信、没有对应居民的信）、`agents` 接入 coding agent（远程 MCP 链接、Claude Code / Codex / Cursor 的接入命令（点一下复制）、没设置公网链接时的提示、已授权的 agent 与撤销）、`feishu` 飞书（扫码接入、发测试消息、断开）、`game` 游戏服（地址、两个 Terraria 游戏服的开关；不能一键开关时给出要运行的命令）、`version` 版本（当前与最新版本、检查新版本、「立即升级」或要运行的命令、升级中与失败的状态；新版本起来后自动刷新）。这一页不显示「发布」 |
| `/models` | 旧地址，跳到 `/settings`（「模型」标签） |

## 结构

| 路径 | 说明 |
|---|---|
| `src/components/city/` | 侧视像素城市（PixiJS）：`draw.ts` 把 `TownLayout` 图元与人物外观画成像素，`palette.ts` 天空随模拟时钟变化，`CityCanvas.tsx` 负责拖拽、缩放、聚焦与 HTML 叠加层（气泡、名牌、地名）。`mode="horizon"` 是其他页面页脚的街道 |
| `src/components/Shell.tsx` | 顶栏（城 / 产品 / 人、累计花费、有新版本或正在升级时的升级标记（仅管理员，点开是「设置 › 版本」）、世界时钟、Terraria 浮层（地址点一下复制、两个游戏服此刻开没开；开关在「设置 › 游戏服」）、语言、明暗主题、退出、设置入口（仅管理员）、「发布」）、登录页（标志的悬停提示是当前版本）、页脚街道（跟在内容后面，不盖住内容）。语言与主题是每位访客自己的显示偏好（访客也要用，设置页只对管理员开放），所以留在顶栏 |
| `src/components/UsingNow.tsx` | 此刻在用某个产品的人：`UsingRow`（一个人一行，产品页带屏幕缩略图、城首页紧凑版点了选中人物）、`UsingNowPanel`（产品页顶上的「此刻在用」） |
| `src/components/Mail.tsx` | 收件箱列表（人物页、使用过程、设置页的无主信共用） |
| `src/components/Publish.tsx` | 发布对话框：网址、名字、一句话（`openPublish()` 可从任意页面打开）；居民还收不到真实邮件时提醒一句（管理员可以直接去设置）；有随包示例产品在跑时，左下角的「示例」可以一键填好 |
| `src/pages/` | `World`、`Products`（含 `useLiveFunnel`：接口人数 + 实时帧）、`Launch`（含清零 / 下线的确认对话框 `Lifecycle`）、`People`、`Person`、`Session`、`Human`、`Settings`（标签栏、公网链接与居民邮箱）、`SettingsPanels`（coding agent、飞书、游戏服、版本）、`Models`（`ModelsPanel`，设置里的「模型」标签） |
| `src/lib/` | API 客户端与查询（`useLaunches`、`useLaunch`、`useLaunchReport`、`useEngineering` …）、WebSocket 实时 store（`snapshot`、`live`、`say`、`launches`）、中英双语文案与标签；`update.ts` 版本与升级的共享状态（顶栏标记与「设置 › 版本」共用：点了升级后记在 sessionStorage，版本号变了就刷新页面）；`live.ts`「此刻在用」的唯一定义（`running` / `waiting_human`，不是回放；排队 `planned` 不算）、`useUsingNow(appId)` 从实时快照取此刻在用某个产品的人、`placeName`；`clipboard.ts` 复制到剪贴板（局域网 IP 走纯 http 时 `navigator.clipboard` 不存在，退回 `execCommand`）|
| `src/design-system/tokens.css` | PlutoKeating design system token 副本（整体替换更新） |
| `.impeccable/surfaces/apps-web.md` | 设计方向契约（开发用，不打包） |

## 约定

- 不在功能旁加说明性小字；用布局、图标、交互表达。
- 颜色只来自 token，两处例外：城市画布上的地名用固定的浅色（天空只跟世界时钟走，不跟界面主题）；飞书二维码用白底（为了能扫）。琥珀只用于「此刻 / 正在发生 / 指向的就是它」；每个视图至多一个骨白主按钮（顶栏的「发布」；设置页不显示「发布」，各标签里各自至多一个：「模型」的「保存」、「居民邮箱」的「开通」、「飞书」的扫码接入、「版本」的「立即升级」）。
- 人数一律标注「模拟」；技术信号只出现在「工程附录」。
