## 已知局限与没有验证到头的地方

完整清单见 [`DECISIONS_2026-11-15.md`](DECISIONS_2026-11-15.md) §6。

- macOS / Windows 的安装路径没有在真机上装过。
- 模型的真实调用只在 Vertex 上的 Gemini 验证过，其他供应商只有协议层的模拟测试。
- 飞书：重写后的渠道（收消息、流式卡片、确认与居民卡片、按钮回调、推送、看板卡、加急、云文档导出）只在模拟的飞书接口上测过；二维码能拿到，还没有用真实账号扫码用过。飞书那边一键创建应用时实际给了哪些权限，以扫码结果为准（不认识的权限名会被确认页静默丢掉）。
- GitHub issue 的开设与关闭后的自动验证只有单元测试，没有对真实仓库跑过。
- 自然流量下的点开率取决于模型对「这个人此刻会不会点」的判断，没有用真人数据校准；一个没有评分的新产品，一个模拟日里可能没有人自己点开。
- 需要较深使用才暴露的问题依赖回访与更多人次。
