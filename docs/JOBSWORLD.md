# JobsWorld：这座城

JobsWorld 是 Jobs 里的那座城：乔布斯镇（Jobs Town）。约两百位居民住在里面，按各自的日程过日子；你把产品发布进来，他们在生活里遇到它。同一座城有三种看法：网页上的侧视像素小城、原版 Terraria、tModLoader——三者共用同一份城镇布局和同一个实时状态。

本文说明城本身：它由什么组成、谁在驱动、消息怎么流动。发布主线见 [`ARCHITECTURE.md`](ARCHITECTURE.md)，规则细节见 [`packages/jobsworld/docs/README.md`](../packages/jobsworld/docs/README.md)，游戏端见 [`game/README.md`](../game/README.md)。

## 1. 城里有什么

| | |
|---|---|
| 城镇 | 一条 1356 格宽的街：5 栋住宅（共 120 套）、学校、公园、公交站、地铁站、写字楼、咖啡店、餐馆、超市、图书馆、医院、工厂，共 16 个地点，外加街道与地铁隧道。布局写在 `config/jobsworld/town.yaml`，由 `computeLayout()` 算成与渲染方式无关的图元、地点和落脚点 |
| 居民 | 新装好时 199 人：14 位手写人物（`config/personas/`）加随包的 185 位居民（`config/population/residents.jsonl`，中国与英语区约各一半）。每个人有家庭与住处、工作地点、收入与钱包、家人同事邻居朋友的关系网，以及城里发的邮箱和手机号。每个人还有自己出门与吃喝玩乐的样子：有空时做什么、一年出几次远门、和别人一起出去时是拿主意的还是跟着走、花钱和分账的习惯、吃饭的忌口与雷点，以及几件过去出游、聚餐时留下的往事（依据是 [`research/`](research/README.md) 里的出游与聚餐调研；人物页的「出门与吃喝」）。邮箱用户名像真人自己起的（拼音姓名、名字加出生年、昵称加吉利数等，只有小写字母和数字，`packages/jobsworld/src/mailhandle.ts`）；在「设置」里开通居民邮箱后，域名是公网链接的主机名，真实产品的验证邮件能收到（见 [`INSTALL.md`](INSTALL.md)「居民邮箱」） |
| 一天 | 每个人按职业和家庭情况有一份日程（17 种角色，周末另有安排，`config/jobsworld/agenda.yaml`）：起床、通勤、上班上学、吃饭、回家、睡觉。饿、精力、想找人说话、压力、心情按规则随时间变化，并会临时改写日程（饿极了先去吃、困了早睡、闷了找人聊）。在外面吃饭花钱，发薪日入账 |
| 时间 | 一个世界时钟，默认与现实 1:1，可以暂停、调速（最高 600 倍）、跳到某个时刻。有人正在使用产品时，时钟最多按 4 倍走，免得他被生活催着走 |
| 事件 | 管理员可以在某个地点制造弱网、拥挤、下雨、停电、噪音。在场的人会有反应；正在那里使用产品的人会真的断网、被打断或分心 |

规则决定这些事，不调用模型。模型只在决定点出场：日程里某一段的具体打算（有人点开这个人或他要开始用产品时才补）、注意到一个产品后点不点开、使用时的每一步、用完之后怎么说。

**一个世界**：一个人此时此地在城里的状态——在哪、在做什么、手里是手机还是电脑、身边有谁、还有多久要去做下一件事、饿不饿累不累——就是他使用产品时的处境。这份处境由 `liveContextFor()` 计算，世界服务和引擎用的是同一套函数；用完之后的心情和压力写回他在城里的状态。

## 2. 谁在驱动

```
                         ┌─────────────── 0.0.0.0:7777（对外唯一端口）────────────┐
 浏览器 ── HTTP/WS ──▶   │ apps/gateway  看每个连接的第一个包：HTTP → 接口；       │
 Terraria 原版 ───────▶  │               "Terraria…" → TShock；"tModLoader…" → tML │
 tModLoader ─────────▶   └──────┬───────────────────┬─────────────────┬───────────┘
                                │                   │                 │
                     apps/api (5320)        tshock（容器）        tml（容器）
                     接口 + WebSocket        JobsWorld 插件        JobsWorld 模组
                     + 网页 + 飞书机器人        │                     │
                                │               └────── NATS ─────────┘
                                └────── NATS ──────────┐
                                                       ▼
                     apps/world（世界服务）：时钟、日程、需求、位置、事件；
                     发布引擎（谁遇到了什么 → 决定 → 使用 → 口碑）；
                     把正在进行的使用一步步转播出去
                                │
                     Postgres（权威数据） / MinIO（截图、录像）
```

- **世界服务**（`apps/world`）是唯一的驱动者。它每秒推进一次世界并广播快照；每 1.5 秒读一次数据库里正在进行的使用，把新的一步转播出去（想法会变成头顶的气泡）；每 10 秒让发布引擎算一遍这段时间里谁遇到了什么；需求与钱包每 30 秒落库，时钟每 5 秒落库（所以重启后接着走）。
- **接口服务**（`apps/api`）只读写数据库，并把网页的命令经 NATS 交给世界服务；它订阅 NATS 上的广播，扇出给浏览器的 WebSocket。
- **游戏端**只依赖 NATS 上的 JSON 消息（C# 里自带一个很小的 NATS 客户端，没有额外依赖）。
- 同屏可见的居民有上限（`JW_MAX_VISIBLE`，默认 60），正在用产品的人优先。

## 3. NATS 主题

定义在 `packages/jobsworld/src/protocol.ts`，C# 一侧对应 `game/shared/Protocol/Messages.cs`。

| 主题 | 方向 | 内容 |
|---|---|---|
| `jw.clock` | 世界 → 所有 | `{ date, day, minute, clock, speed, paused }`，每秒一次 |
| `jw.snapshot` | 世界 → 所有 | 可见居民的位置、姿态、正在做什么、需求（饿、精力、孤单、压力、心情）、钱包、手机在不在手边、需求改写日程的原因，以及正在生效的事件。每秒一次，同时写入 KV `jobsworld.snapshot` |
| `jw.persona.<id>.live` | 世界 → 所有 | 某人使用产品的一步：想法、意图、动作、截图证据的 id、心情。JetStream 流 `JW_LIVE` 保留 24 小时 |
| `jw.persona.<id>.say` | 世界 → 所有 | 头顶气泡：想法摘要、对事件的反应、注意到一个产品时闪过的念头 |
| `jw.launches` | 世界 → 所有 | 已发布的产品与各自的人数（看到、注意到、有兴趣、打开过、回来再用、此刻在用、评分）。发布引擎每一轮广播一次，同时写入 KV `jobsworld.launches` |
| `jw.town` | 请求 / 应答 | 城镇布局（游戏端启动时取） |
| `jw.detail` | 请求 / 应答 | 一个人的详情：实时状态、日程、关系网、最近的记忆（游戏里的人物面板用） |
| `jw.ask` | 请求 / 应答 | 向一个人追问，基于他最近一次已结束的使用 |
| `jw.chat` | 请求 / 应答 | 跟一个人连续聊天（飞书、网页、终端里「让我跟某某聊聊」）：带他的身份、记忆、用过的产品和此刻的处境；正在用产品时分心回几句 |
| `jw.notice` | 发布 | 值得告诉开发者的事：一次使用结束、亲历问题第一次出现、结论写好、需要人介入、修好后的自动验证（API 里的飞书推送器订阅） |
| `jw.launches.get` | 请求 / 应答 | 此刻的产品与人数（游戏里 `/jw launches`） |
| `jw.cmd.clock` / `jw.cmd.event` / `jw.cmd.replay` | 命令 | 暂停与调速、制造事件、在原地点回放一次使用 |
| `jw.cmd.publish` / `jw.cmd.promote` / `jw.cmd.invite` | 命令 | 发布产品、调宣发（强度、暂停、继续、结束；可以写产品名）、把手机递给几个人 |
| `jw.cmd.lifecycle` | 请求/应答 | `{ launch_id, action: 'reset' \| 'remove', keep_history? }`：清零或下线一个产品。世界服务先丢掉排队的使用、让进行中的使用在当前这一步做完后作废并等它们停下，再清库（`resetLaunch` / `removeLaunch`）。接口在世界服务没在跑时直接清库 |

## 4. 数据

| 表 | 内容 |
|---|---|
| `personas` | 每个人的六层描述（身份、能力、心理、行为策略…），以及「出门与吃喝玩乐」一层（`leisure`） |
| `households`、`residents`、`relations` | 家庭与住处；工作地点、收入、钱包、邮箱与手机号、当前的需求；关系网 |
| `persona_agendas` | 每人每天的日程 |
| `persona_memory_trees` | 每人一棵记忆树（见 `packages/memory`） |
| `persona_avatars` | 头像（接入了画图模型时生成；否则网页用确定性的像素头像） |
| `world_events`、`world_kv` | 城里的事件；世界时钟等要跨重启保留的状态 |
| `sessions.world_context` | 一次使用开始时，这个人此时此地的处境 |

## 6. 三种看法

**网页**（首页就是城）：可拖动、可缩放的侧视像素小城，天空跟着世界时钟从夜到晨到黄昏。点人看他此刻在做什么、在用什么、在想什么、刚才做了什么、接下来去哪，可以向他追问；点建筑看里面的人。右侧「此刻」默认按产品分组，列出此刻正在用每个产品的人（排队的不算），也可以切到全城所有人。

**Terraria**：居民是出现在玩家列表里的角色（不是 NPC），外观按年龄、性别、职业映射；想法以他们的名义发在聊天里，显示在头顶。昼夜跟着世界时钟。`/jw who`、`/jw goto`、`/jw follow`、`/jw info`、`/jw ask`、`/jw launches`，管理员另有 `/jw publish`、`/jw promote`、`/jw invite`、`/jw clock`、`/jw event`、`/jw replay`。tModLoader 版多一个可点击的人物面板和右上角的状态栏。

两个游戏服默认不启动：装好的 Jobs 在网页右上角的手柄里打开，或 `jobsworld game on tshock|tml`；从源码运行时 `docker compose --profile game up -d --build --no-deps tshock`。

## 7. 仍然有效的几个取舍

- 居民在游戏里是「假玩家」而不是 NPC：这样才有名字、外观和头顶的话。
- 一个端口进来，靠第一个包分流，不终止 TLS。
- 地图由 YAML 布局程序化生成；自制地标可以用 `.TEditSch` 蓝图放进 `game/schematics/`。社区蓝图多数没有许可证，只用脚本下载到本机 `data/community/`，不入库、不打进镜像。
- 界面中英双语，默认中文；居民说的话保持他们自己的语言。

## 8. 已知的局限

- 游戏里的角色只有站和走，没有坐、躺的姿态（网页里有）；时装栏是空的。
- 同屏人数受游戏服的玩家槽位限制（默认最多 75 个假玩家槽位，可见上限默认 60）。
- 网页开了访客口令时，tModLoader 面板凭服务端下发的令牌加载截图；原版 Terraria 没有面板，只能看气泡和 `/jw info`。
