# 模型接入

Jobs 自己管理模型调用：管理员在网页的「模型」里从目录选供应商、粘贴凭证、勾选模型、排好顺序，点一次「保存」；运行中的服务几秒内换上新配置。不需要另起模型网关，也不用改配置文件或重启。

实现在 `packages/llm`，管理接口在 `apps/api/src/models.ts`，界面在 `apps/web/src/pages/Models.tsx`。设计方法依据仓库所有者的《多供应商、多凭证、多模型动态配置方法论》（2026-11-15）；本文按它要求的交付内容组织，并明确哪些已验证、哪些还没有。

## 1. 数据概念

| 对象 | 表达什么 | 在哪 |
|---|---|---|
| 供应商目录 | 公共厂商与模型的名称、地址、协议、能力、价格。只是选择时的辅助：不带凭证，也不会改动已保存的配置 | models.dev → `world_kv['llm_catalog']`；拉不到时用随包快照 `config/models/catalog.json` |
| 连接 `ProviderConn` | 一个实际的接入点：名字、地址、协议、启停。同一厂商可以建多个连接 | 配置版本内 |
| 凭证 `CredentialRef` | 某个连接可用的认证材料：稳定标识、启停、脱敏提示、密文引用 | 引用在配置版本内；密文在 `llm_secrets` |
| 调用目标 `ModelEntry` | 某个连接下的一个模型：上游标识、类型（对话 / 向量 / 画图）、能力（看图、结构化输出、上下文）、价格、承担的用途 | 配置版本内 |
| 模型组 `Use` | 应用按用途选模型，不依赖上游名称：`step` 每一步（看图）、`think` 归纳与判断、`locate` 在截图上定位、`embed` 向量、`image` 画图 | 代码里的调用点（角色）映射到模型组：`useOfRole` |
| 全局顺序 `order` | 跨供应商的一套顺序：当前目标不行了去哪 | 配置版本内 |
| 配置版本 | 一次保存的完整内容，不可变；带父版本、摘要、作者、提交标识 | `llm_config_versions`（当前配置 = 版本号最大的一行） |
| 运行快照 | 某个实例此刻采用的版本 | 各进程内存；每个实例把自己的版本写进 `llm_instances` |
| 健康状态 | 近期失败导致的暂时跳过（哪个目标 / 哪把凭证、原因、到什么时候） | 各进程内存，随心跳上报；换配置版本即清空。它不改变管理员的启停意图 |

四种状态各有来源：目录回答「可以考虑哪些」；配置回答「允许用哪些」；快照回答「这个实例用的是什么」；健康状态回答「此刻哪些适合接单」。

顺序只有一套。一类请求的候选 = 全局顺序里，同时满足「勾选了这个用途、连接启用、有启用且没在冷却的凭证、能力够（带图片的请求只进能看图的目标；定位只进同一模型家族的目标）、目标本身没在冷却」的那些。被跳过的目标保留名次并带原因，恢复后回到原位（`candidates()`，纯函数，界面的路由预览用的也是它）。

## 2. 一次保存经过什么

```
界面草稿（内存；凭证明文只在这里，保存或放弃后清掉）
  → 点「保存」：先看到与线上的差异（新增 / 移除、顺序、凭证数、每个用途此刻可用的目标数）→「确认保存」
  → POST /models/publish { base_version, submit_id, config, new_secrets }
  → 同一事务内：取咨询锁 → 同一提交标识已发布过则原样返回（回执丢了再提交不会重复）
      → 线上版本 ≠ base_version 则拒绝（409，草稿留在界面，可「载入最新版本」或「以我的草稿为准」）
      → 新凭证加密写入 llm_secrets → 整理并校验配置 → 校验凭证引用（存在、未撤销、属于同一连接）
      → 已有凭证的连接换了主机名则拒绝 → 撤销这一版不再引用的凭证 → 写入新版本
  → 本实例立即换上新快照；其他实例每 5 秒核对一次版本号（POLL_MS），发现更大的版本就换上并上报
  → 界面的状态行显示每个在线实例用的是第几版
```

任何一步失败，整次保存不发生：不会出现只存了凭证、没存模型的半截状态。

**生效的边界**（按四个时刻分别说）：持久写入 = 事务提交；开始分发 = 同时（没有单独的通知，靠轮询）；实例换上 = 本实例立即，其他实例最迟 5 秒；新请求实际使用 = 实例换上之后开始的请求。一次请求在开头固定快照并用到底（重试、换目标都在同一版内）；正在进行的一次使用，下一步的请求就会用上新版本。实例只接受版本号更大的快照，迟到的旧读取不会把旧内容填回去。

**回滚** = 把旧版本的内容作为一个新版本重新保存，时间顺序完整。旧版本里后来被撤销的凭证不会回来：对应条目被去掉，界面提示去掉了几把。

**凭证**：AES-256-GCM 加密，密文绑定所属连接（搬到别的连接上解不开）。主密钥来自环境变量 `JOBS_SECRET_KEY`（安装时生成），与数据库分开存放；从源码运行且没设置时在 `data/secret.key` 生成。读取配置只返回脱敏提示（末四位，或 Google 凭证里的账号 / 项目名；文件引用另加 `file`）。凭证只在真正发起调用前解密，按快照版本缓存在内存里。

## 3. 一次调用经过什么

```
调用点说「我是哪个角色」→ 模型组 → 固定快照 → candidates()（带图片则要求能看图）
  → 没有任何候选：报错并说清缺什么（哪些目标因为什么被跳过）。没有隐藏的备用目标
  → 按顺序取目标 → 在它启用且没冷却的凭证里随机取一把 → 解密 → 发给上游
  → 成功：有结构要求则校验；不合格让同一目标改，最多两次，还不行换下一个
  → 失败：归类 → 按下表处理 → 同目标再试 / 换凭证 / 换目标 / 结束
  → 每一次尝试写一行 llm_traces：配置版本、模型组、实际目标、凭证脱敏标识、第几次、错误类别、用量与费用估计
```

一次业务请求最多发起 6 次上游调用（`MAX_ATTEMPTS`），包含重试、换凭证、换目标和修正格式。

| 上游出了什么事（`classifyError`） | 怎么办（`reaction`） | 防误伤 |
|---|---|---|
| 凭证无效或过期 `auth` | 这把凭证冷却 10 分钟；同一目标换另一把；没有了再换目标 | 不把一把凭证的问题当成整家供应商坏了 |
| 限流、额度不足 `rate_limit` | 这把凭证冷却（尊重上游给的 `Retry-After`，5 秒到 10 分钟之间）；换凭证，再换目标 | 冷却记在真正失败的凭证上，接替的目标不受牵连 |
| 模型不存在或无权限 `not_found` | 这个目标冷却 10 分钟；直接换目标 | 换凭证重试同一个错误没有意义 |
| 连不上、超时、5xx `transient` | 同一目标退避加随机间隔后再试一次；还不行，目标冷却 20 秒并换下一个 | 不让大量请求同时再去撞一个出故障的上游 |
| 内容太长 `context`、不支持这项能力 `capability` | 换下一个目标；不冷却 | 目标本身没坏，只是干不了这一件事 |
| 内容安全拒绝 `content` | 到此为止，报错 | 不靠换供应商绕过安全策略 |
| 上游不认某个可选参数（温度、推理强度、`max_tokens`、结构化输出格式） | 去掉它在同一目标上重发，并记住这个目标不认它 | 只去掉提示性的参数；结构化输出改为在提示里给 schema，结果照样校验 |
| 其余被拒绝的请求 `bad_request` | 换下一个目标 | — |

**协议适配**（`adapters.ts`）：`openai`（OpenAI 兼容：绝大多数供应商，包括 Google AI Studio 的兼容入口）、`anthropic`（Messages 接口；结构化输出靠提示里的 schema 加校验）、`vertex`（粘贴 Google 凭证 JSON——服务账号密钥或 `gcloud auth application-default login` 生成的文件——换成访问令牌后走 Vertex 的 OpenAI 兼容入口；向量与画图走 Google 原生接口）。

**Vertex 凭证也可以是文件引用**：在凭证框里粘贴 `{"file": "/容器里的绝对路径/application_default_credentials.json", "project_id": "<项目>"}`（`project_id` 可省略，省略时用文件里的 `quota_project_id` / `project_id`）。保存的只是这个引用；每次换访问令牌前都重新读文件，文件内容变了就立即换新令牌（`googleCred`、`googleToken`）。适合 gcloud 登录有有效期（组织策略要求每天重新登录）的情况：宿主机上重新 `gcloud auth login` / `gcloud auth application-default login` 之后，不用回到「模型」页重新粘贴。文件要挂进容器，见 [`INSTALL.md`](INSTALL.md)「用本机 gcloud 登录的 Vertex 凭证」。登录过期期间换令牌会失败，按「凭证无效」处理（这把凭证冷却 10 分钟），所以重新登录后最迟约 10 分钟恢复。

**出站保护**：只发往 http/https；不跟随跳转（凭证不会被带到别的地址）；拒绝云主机的元数据地址（保存时看字面，连接时再看解析结果）。本机和内网地址是允许的——本地模型服务（Ollama、LM Studio）是正当用途，而且只有管理员能配置连接。

**自己发请求的组件**：Midscene（在截图上定位）和示例产品里的 AI 功能走 OpenAI 兼容入口 `…/<step|think|locate>[/<家族>]/v1/chat/completions`（`endpoint.ts`）：按模型组路由到已保存配置里的目标，替换成上游模型名，失败时按全局顺序换下一个（最多 3 个，只转发给 OpenAI 兼容协议的目标）。世界服务在回环地址上起一个只有本进程知道口令的入口给 Midscene；API 在 `/api/v1/llm/*` 提供同样的入口。Midscene 的提示与坐标格式按模型家族定（`locateFamily`：gemini、gpt-5、qwen-vl、doubao、glm-v、ui-tars…），所以入口地址里带家族，一次会话只会转发给同一家族的目标；认不出家族的模型不能勾选「定位」。

**没接入模型时**：世界照常运转，发布引擎暂不运行（没人能做决定、也没人能用产品）；管理员第一次打开网页会被带到「模型」页。接入并保存后几秒内自动开始。向量与画图是可选的：没接入向量模型时记忆检索用本地的字符哈希向量，没接入画图模型时头像用确定性的像素头像。

## 4. 管理界面

`/models`（仅管理员）。自上而下：状态行 → 各用途此刻的首选目标 → 添加供应商 → 连接卡片 → 全局顺序 → 版本。

- **状态行**（滚动时吸顶，「保存」始终可见）：线上已同步时显示版本号和每个在线实例是否已换上；有改动时显示「有未保存的改动」；别人先保存了则显示冲突，并给出两个选择。有未保存的改动时离开页面会提醒。
- **各用途的首选目标**：每一步、归纳、定位（必需），向量、画图（接入了才显示）。悬停可见完整的接替顺序；必需的用途没有可用目标时标红。这就是路由预览：由服务端用同一个 `candidates()` 对草稿计算，不发任何真实请求。
- **添加供应商**：点开即是目录（常用的在前），输入即过滤；选中后名字、地址、协议自动填好，只需粘贴凭证。也可以建自定义连接（填地址、选协议）。
- **连接卡片**：折叠时显示名字、启用的凭证数、已选模型数、启停开关。展开后依次是连接、凭证、模型，删除在最下面。已有保存过的凭证时地址不可改。
- **模型**：可搜索的勾选列表，带「仅看已选」、看图 / 可定位标记、上下文长度、价格（目录里没有价格时写「价格未知」）。勾选即进入全局顺序末尾，并按能力给出默认用途（可改）。目录里没有的模型可以按标识自行添加。
- **全局顺序**：每行是名次、拖动手柄、连接 / 模型、用途、被跳过的原因。可以拖；可以点「置顶 / 上移 / 下移 / 置底」；键盘上空格拿起、方向键移动、空格放下、Esc 取消，读屏会播报新位置。
- **测试**：只对已保存的配置测，有未保存的改动时不可用（测的和看到的必须是一回事）。对话模型依次测文字、看图（如果能看图）、结构化输出；结果绑定配置版本、凭证脱敏标识与时间，配置变了之后标为「待复核」。测试成功只说明「这一版里，这个目标用这把凭证，此刻能做这一件事」。

## 5. 为什么自己做，而不是接一个现成的网关

独立的模型网关（例如 LiteLLM）通常把模型写在配置文件里：改配置要重启，凭证靠挂载文件，装好之后的用户没有界面可用。产品决策要求「一行安装、首次打开网页就能接入模型」，并且只有一个应用在用这些凭证，所以选择应用内路由：部署面小，和「使用过程 / 花费记录 / 发布引擎」直接结合。代价是协议变化、错误归类要自己维护。只由这一层负责换目标与重试预算（底层 HTTP 调用不自动重试），应用层只管业务结果。

复用的部分：models.dev 目录（选型与初始元数据）、各家的 OpenAI 兼容入口（一个适配器覆盖绝大多数供应商）、Midscene（定位）。

## 6. 验证了什么

| 层 | 证据 |
|---|---|
| 规则（`tests/models.test.ts`，28 项） | 顺序整理、身份唯一、用途随类型与能力收敛；候选与每一种跳过原因；冷却的目标保留名次；错误归类与处理方向；密文绑定连接；Google 凭证的文件引用（现读文件、内容换了就用新的、项目优先级、读不到与相对路径的报错）；目录收敛与拒收 |
| 故障模拟（同上，本地假上游） | 一把凭证失效只隔离那一把；限流尊重恢复时间并转到下一个目标，冷却记在失败的一方；临时故障先退避重试再换目标；带图请求不进不能看图的目标；结构不合格让同一目标改；上游不认的可选参数去掉后不再带；内容安全拒绝不换供应商；总尝试数有上限；没有候选时说清原因；兼容入口按家族转发 |
| 真实数据库（2026-11-15，本机） | 旧版本提交被拒绝（409）且草稿不丢；同一提交标识重复提交得到同一版本；凭证明文不出现在任何返回里；删掉的凭证被撤销，回滚到含它的版本时不复活；停掉唯一能做「每一步」的模型后就绪状态变为否、世界服务暂停发布引擎并在几秒内换上新版本；已有凭证的连接换主机名被拒绝 |
| 真实调用（2026-11-16，本机，Vertex，文件引用） | 引用指向本机 gcloud 的 `application_default_credentials.json`（`gcloud auth login` 写出的用户凭证，文件里没有项目，项目写在引用里），换到令牌并经 OpenAI 兼容入口调用 Gemini 返回 200 |
| 真实调用（2026-11-15，本机，Vertex，粘贴 ADC JSON） | 文字、看图、结构化输出、向量、画图各测一次通过；世界服务经新路由跑完多次真实使用（每一步、Midscene 定位经本地兼容入口、事后归纳），两个实例都报告同一配置版本 |

还没有验证的：除 Vertex 以外的供应商（OpenAI、Anthropic、各家兼容入口）只有假上游下的协议测试，没有用真实凭证调用过；多台机器、多个同类实例之间的传播；流式输出中途失败（兼容入口的流式是原样透传，中途断了不会接续）。

## 7. 已知限制

- 传播靠轮询，没有推送通知，也没有「要求最低配置版本」的请求。单机部署下最迟 5 秒。
- 健康状态只在进程内，各实例各记各的；同一连接的多把凭证被视为等价池，不识别它们是否共享同一个账号额度。
- 没有同组内按权重分流，没有按费用或质量自动选模型：顺序完全由管理员排。
- 测试只覆盖文字、看图、结构化输出、向量、画图；定位能力没有单独的测试（靠「能看图 + 认得出家族」推断）。
- 撤销凭证会阻止之后的新调用，已经发出去的请求收不回来。
- 界面一次只有一份草稿；冲突时只能二选一，没有逐项合并。
- 中途接入或更换向量模型后，已有记忆的向量不会重算：新旧向量不在同一个空间里，旧记忆被想起来的概率会下降。建议在发布第一个产品之前就把向量模型定下来（或者一直不接，用本地向量）。
