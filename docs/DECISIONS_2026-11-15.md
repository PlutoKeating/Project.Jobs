# Jobs 重塑：产品审视结论与拍板决策（2026-11-15）

> 状态：已由产品负责人逐题审核通过（2026-11-15）。本文是这次重塑的唯一决策记录：§1–§5 是当时的审视与决策原文，§6 是落实情况。与早期设计稿 [`history/SPEC_v0.2.md`](history/SPEC_v0.2.md) 冲突时以本文为准；实现与本文不一致时以代码为准并回写 §6。

## 1. 目标用例（产品负责人原述，摘要）

使用者是 OPC 创业者：有一定技术、产品、商业和审美能力，用 vibe coding 能很快做出东西，但没有足够的时间精力验证「这个产品是不是人人觉得好用」。

期望：做出来的产品直接在 **JobsWorld** 里「发布上线」。JobsWorld 是一个虚拟世界，住着尽可能多样的人（各年龄、职业、身份、阶层、处境、生活/工作/学习场景），每个人都是有生理本能、有社会属性和社会需求的生物。使用者站在上帝视角调节宣发，让虚拟人群的注意力自然转移到产品上；或者直接把产品给到某些人。虚拟人自己决定感不感兴趣、用不用、好不好用。

最重要的约束：**用户不是技术大牛**。不假定用户能解决任何 bug，不假定用户理解技术细节，用户看不到产品体验以外的任何东西（源码、console、视觉上看不到的内容）。虚拟人只通过看、点击、滑动、长按、鼠标、键盘使用产品。长期、多次、想用才用，最终汇总成报告。

## 2. 审视结论（重塑前的现状；这些问题正是后面的决策要改掉的，现在的系统见 §6 与 `ARCHITECTURE.md`）

一句话：做出来的是一台给工程师用的评测仪器，外面套了一座不相干的小城；主语是「评测批次」，应该是「发布」。

### 调研结论（部分只来自搜索摘要，未逐一核实一手页面）

- 只凭截图操作 Web、手机、桌面三端在 2026 年底已可行（多家模型原生支持 computer use；Midscene 一套 SDK 覆盖多端）。iOS 与 macOS 无法在 Linux 主机上运行。
- 没有找到开源的「发现 → 下载 → 留存」LLM 漏斗模拟。可借鉴：OASIS 的「按小时活跃概率 + 推荐流曝光」；AgentSociety 早期论文的「需求 → 计划 → 行为」；经典 Bass 扩散模型做骨架，LLM 只做个体判断。
- 人口不能靠「多生成一些」换多样性（LLM 会压平群体内差异）。可行做法：属性骨架从统计分布抽样，LLM 只填叙事。
- LLM 用户比真人更聪明、更配合、更少离开；要靠机制限制而不是提示词。合成用户在「哪里卡住」上可信，在满意度、付费意愿、留存的绝对值上不可信。
- eWave：已发布的 `@plutokeating/ewave` 是不调用模型的记忆结构容器（树/图、时间切片、支撑与冲突边），不含人格代码；其组会报告的「海与浪」人格数据系统只有设计。可用于记忆层；报告中值得借鉴的思想：身份与价值观钉住、对产品的态度有界可变、多次独立经历才改变全局信念、记忆以「信息」而非「指令」进入提示词。

## 4. 实施中的解读与约束

1. **ewave 只读**：只把已发布的 `@plutokeating/ewave` 当普通依赖使用；不修改其源码，不触碰其项目目录。包本身没有的能力（数据库持久化、单写者保证、每人节点数上限）在本仓库的适配层实现。
2. **「落点可借 DOM」的边界**：DOM 只用于把虚拟人已经从截图里认出的目标换算成坐标；任何 DOM 文字都不进入虚拟人的想法。
3. **工程附录的来源**：无障碍扫描、控制台与网络错误、专家式启发检查只进工程附录；体验结论只由虚拟人亲历的事件（预期落空、困惑、放弃、离开、称赞）产生。技术信号同时用于判断「产品的错还是模拟器的错」。
4. **成本不设上限**：界面与飞书持续显示已花费。
5. **校准先不管**：报告中的数字一律标注为模拟；已有的可信度标签保留。
6. **Terraria**：每个阶段新增的世界能力都要同步到游戏端的数据通道（NATS 消息）；游戏端代码沿用。
